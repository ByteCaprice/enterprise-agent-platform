# 文档与文件分发策略

本项目采用“公开资料白名单、本地资料默认保留”的方式，避免把整个工作目录当作发布内容。

这里的“公开”指**经审阅后可进入获授权的 remote 仓库或交付范围**，不代表开源许可，也不代表已经获准向任意第三方发布。即使 remote 是私有仓库，也不应保存可用凭据或客户材料。

## 分类

| 类别 | 位置或示例 | 是否进入 remote |
| --- | --- | --- |
| 产品与框架说明 | 根 README、贡献说明、本文及文档导航列出的公开指南 | 可，经内容审阅后 |
| 稳定使用契约 | 功能与架构、API、通用运行边界、开发规范、产品级路线图 | 可，不包含内部环境细节 |
| 内部设计与工作记录 | `.local/`，内部评审、需求对照、交接与环境操作记录 | 不进入，保留本地 |
| 内部需求和原型 | 本地需求基线、原型 HTML、草拟方案 | 默认不进入，不能为清理而删除 |
| 实际配置与秘密 | `config/`、`.env*`、本地包仓库配置、Key/证书私钥、真实策略和 MCP 目录 | 不进入；建议存于仓库外或受控密钥系统 |
| 客户与运行数据 | 文档样本、图片、录屏、请求/模型原文、导出、数据库备份、抓包 | 不进入，文件名像测试样例也不构成分发授权 |
| 本地工具和产物 | IDE/助手数据、缓存、虚拟环境、node_modules、build/dist、日志 | 不进入 |
| 源码与依赖元数据 | 经审阅的源代码、测试、平台迁移、公共来源锁文件、必要运行资产 | 可，仍需内容审阅 |

不要把内部设计或事故记录复制进公开文档。公开文档描述稳定契约和当前限制；内部文档可以记录未决方案、环境事实和处置过程，两者不自动互相同步。

## 明确的公开入口

公开 Markdown 列表由 `scripts/repository_policy.py` 维护，`.gitignore` 只放行对应路径：

- 根 `README.md`、`CONTRIBUTING.md`。
- `docs/README.md`、`overview.md`、`api.md`、`frontend-integration.md`、`deployment.md`、`development.md`、`roadmap.md`、`repository-policy.md`。
- `tests/fixtures/trade_documents/README.md` 仅说明样本分发限制；不包含或授权分发样本。

内部资料统一优先放在 `.local/`。原本被忽略的需求基线和环境配置可继续保留原位置，不要求移动或删除；公开文档不得依赖这些文件的链接才能阅读。

新顶层文件/目录、新 Markdown、JSON/YAML 配置和脚本默认不自动获准分发。新增公开资源时须同时审阅内容、调整明确白名单，并运行边界检查；**不对 `*.example` 做全局豁免**。

## 配置、模板与锁文件

- 只允许审核过的空白部署模板；填写后的副本放在仓库外或 `.local/`。模板必须没有可用密码、Token、真实主体或私有连接信息。
- 保留 `uv.lock` 和新 Pi 适配器的 `package-lock.json`，它们是可复现依赖元数据，不是缓存。
- 锁文件中的下载来源须经审阅，不能带认证 userinfo、签名查询参数、内部仓库地址或本机绝对依赖路径。
- 私有镜像、索引和认证在被忽略的本地配置或受控 CI 环境中提供，不能为方便安装而写进公共锁文件。
- 平台初始化源码位于 `infra/platform_migrations/`，包含固定 baseline SQL；它们属于程序资产，不能当作数据库导出或备份忽略。

## 三条分发边界分别保护

| 路径 | 保护方式 | 不能替代什么 |
| --- | --- | --- |
| Git / remote | 根白名单、私有路径忽略、工作区及索引检查 | `.gitignore` 不能保护已跟踪内容，也不是完整内容分类器 |
| Docker 构建上下文 | `docker/platform/Dockerfile.dockerignore` 的独立允许/排除规则 | 不能假设 Git 忽略项就不会发给构建器 |
| Python 发行物 | 包发现排除、`MANIFEST.in`、wheel 内容检查 | 不能假设本地文件未提交就不会被打包 |

分发边界与代码依赖须同时成立：源码、测试和文档不能依赖被忽略的本地模块。新增组件时，应一并审查运行依赖、测试入口、材料来源和发布资产。

## 公开发布

公开发布直接使用本仓库，不需要创建其他源码副本。仅提交审核后的通用源文件、测试、公开文档、公共依赖元数据和空白模板；私有配置、真实样本、个人工具记录及缓存不属于公开内容。`.gitignore` 明确屏蔽这些类别，分发检查器独立核对路径与内容。

新公开项目应使用独立历史，不能导入未经审核的提交、作者身份、旧 remote、备份或 Git 对象库。配置目标 GitHub 仓库前核对地址，提交前明确选择希望公开的 Git 名称和邮箱（可使用 GitHub noreply 邮箱）；不要从本地环境自动推断或复制身份信息。

检查器不是完整的秘密或个人信息扫描器；发布前还须审阅内容、扫描秘密并确认代码权属和发布授权。当前未指定开源许可证，须由权利人选择并补充；第三方许可证、版权和必要署名不能因匿名化而删除。未明确授权时不自动 commit、push 或发布。

## 提交前检查

```bash
python -m scripts.check_repository_files
git status --short -- .
git diff --cached --stat -- .
```

检查器只读，限定本项目路径；会核对忽略规则、公开文档链接、未批准路径、可识别凭据及依赖来源，并扫描**工作区候选内容和 Git 索引中的实际 blob**。工作区已清理不代表旧的暂存内容也已清理。符号链接、未审核二进制和超大文件要求额外审阅。

输出只含问题类别、文件位置及必要行号，不输出疑似秘密、URL 或原始内容。它不替代人工评审、材料授权或完整密钥扫描；通过检查也不是上传授权。

### 已跟踪或已经上传的私有文件

- 新增忽略规则不会从索引或历史中移除它们。先确认影响范围，再从索引撤下并保留本地副本；不要直接删除工作文件。
- 不使用 `git add -f` 绕过分发边界，也不直接执行覆盖范围不明的批量删除、清理或历史重写。
- 若真实凭据已经上传，单纯删除文件不够，需撤销/轮换并按明确授权处理历史及镜像/缓存。
- 本项目可能位于更大的父 Git 工作区内。提交前确认 Git 根目录，不用会捎带旁边项目的根目录批量操作。

文档完善、文件整理、检查通过、构建命令可用，都不自动授权 commit、push、发布制品、执行迁移或部署。
